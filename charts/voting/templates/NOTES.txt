Release {{ .Release.Name }} deployed to namespace {{ .Release.Namespace }}.

1) Watch the pods come up:

   kubectl get pods -n {{ .Release.Namespace }} -w

2) The two public Services are AWS LoadBalancers and take 1-2 minutes:

   kubectl get svc -n {{ .Release.Namespace }}

   NAME     TYPE           CLUSTER-IP     EXTERNAL-IP
   vote     LoadBalancer   ...            a1b2c3...-1234567890.eu-west-1.elb.amazonaws.com
   result   LoadBalancer   ...            d4e5f6...-1234567890.eu-west-1.elb.amazonaws.com

3) Copy the external addresses once they are assigned:

   VOTE_HOST=$(kubectl get svc vote -n {{ .Release.Namespace }} -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
   RESULT_HOST=$(kubectl get svc result -n {{ .Release.Namespace }} -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')

   echo "vote   -> http://${VOTE_HOST}:8080"
   echo "result -> http://${RESULT_HOST}:8080"

   If your cluster reports an IP instead of a hostname (for example on
   other clouds), use .status.loadBalancer.ingress[0].ip instead.

4) Useful release commands:

   helm history {{ .Release.Name }} -n {{ .Release.Namespace }}
   helm rollback {{ .Release.Name }} 1 -n {{ .Release.Namespace }}

Note: PostgreSQL stores its data in an emptyDir volume, so the data disappears
when the pod is deleted. Replacing it with a PersistentVolumeClaim is the
obvious later improvement.
